# でも、今までもETLツールってあったよね？

娘「でもパパ」  
娘「ETLツールって、昔からあったじゃん？」  
娘「なんで今さらAIでやるの？」

ワイ「ええ質問やな」

- 従来のETLツールは**GUIが複雑**で初心者にはハードルが高かった
- 設定ファイルも**ちょっと変更しただけで壊れやすい**
- 新しいデータソースに対応するのも**面倒くさい**

ワイ「でもAIを使えば──」

> AIちゃん「最新のマイグレーションを反映して、パイプライン設定を更新しました。」
> AIちゃん「このソースにはNullが多いので除去しておきました」
> AIちゃん「日付形式の変換も自動でやっておきました」

ワイ「──みたいに**気が利くETL処理**が可能になるんや」

娘「おお〜、まるでデータエンジニアのアシスタントみたい！」

娘「じゃあさ、昔からあるETLツールって、もういらないってこと？」

ワイ「いや、そう単純な話やないで」
ワイ「**どっちが偉いかやなくて、何を取って何を捨てるかの話**やねん」

娘「どういうこと？」

ワイ「判断軸を並べてみると、こんな感じや」

| 判断軸 | 従来のETLツール | AI ETL |
| --- | --- | --- |
| **柔軟性** | 決められた範囲では強い | 自然言語でなんでも頼める |
| **制御性** | 設定した通りにしか動かない | 毎回同じ動きをする保証はない |
| **学習コスト** | GUIや独自概念の習得が必要 | 日本語で頼めるから低い |
| **監査のしやすさ** | 設定ファイルがそのまま仕様書になる | 「なんでそうしたか」の追跡が課題 |
| **再現性** | 高い（同じ入力なら同じ出力） | プロンプトやモデル次第で揺れる |

ワイ「たとえば**毎日決まった時間に、絶対同じ結果が欲しい基幹処理**なら、従来ツールの堅さが効く」
ワイ「逆に**仕様がコロコロ変わる分析の前処理**なら、AIの柔らかさが効くんや」

娘「『便利かどうか』じゃなくて、『何を大事にするか』で選ぶんだね！」

ワイ「せや。新しいもんに飛びつく前に、**何を捨ててもええか先に決める**のが大事やで」

# どうやって使うの？

娘「で、どうやってそのAI ETLを使うの？」

ワイ「たとえばこんな流れやな」

1. **ChatGPTにETLのタスクを指示**  
   （データの場所、目的、加工内容など）

2. **スクリプトやツール設定を自動生成**  
   （Airflow DAG、dbtモデル、SQL変換など）

3. **CLIやAPI経由でジョブを実行**  
   （MCPサーバ経由でもOK）

4. **進捗をChatGPTに報告させる**  
   （Slack通知、ログ要約などもできる）

娘「もうAIがデータ移行チームの一員じゃん！」

ワイ「ほんまそれな」

# 気をつけることは？

娘「でもAIが勝手にデータいじるって、ちょっと怖くない？」

ワイ「せやな、特に気をつけるべきは──」

- **実行環境をサンドボックス化**する  
- **読み取り専用の権限から始める**  
- **ログとレビューは人間が見る**  
- **いつでもロールバックできるようにする**

ワイ「AIに権限を渡すときは、ちゃんと安全設計しないとな」

娘「でもさ、それ全部やっても、いきなり全部任せるのはまだ怖くない？」

ワイ「ええ勘しとるな。せやから**いきなり全部は任せへん**」  
ワイ「**段階を踏んで、信頼を積み上げていく**んや」

1. **まずは読み取り専用**：AIにはデータを読ませて、提案だけさせる
2. **次は人間レビュー付き**：AIが作った変換スクリプトを、人間が確認してから実行する
3. **最後に限定的な自動化**：レビューで実績を積めた定型処理だけ、ロールバック前提で任せる

ワイ「ポイントはな、**AIが賢いかどうかで決めるんやない**ねん」  
ワイ「**間違えたとき、人間が気づけてすぐ戻せる範囲か**──それで任せる広さを決めるんや」

娘「ふ〜ん。でもそれ、パパの会社の偉い人にはなんて説明するの？」

ワイ「うっ、痛いとこ突くなあ……」  
ワイ「『AIがすごいんで任せます！』やと、まず通らんやろな」  
ワイ「説明するなら、こうや──」

> 「最初は読み取り専用で提案だけさせます。本番への書き込みは人間の承認制です。失敗しても戻せる範囲からしか広げません」

ワイ「──**任せる範囲と、戻せる仕組みをセットで伝える**のが筋やと思うで」

娘「すごい技術の話じゃなくて、リスクの話に翻訳するんだ！」

ワイ「せや。偉い人が知りたいのは仕組みやのうて、**何かあったときに止められるか**やからな」

# まとめ：AI時代のETLとは

- 従来のETLは**人間が組み立てて使う**ものだった  
- 今は**AIに設計も実行も任せられる**時代に突入  
- ただし選ぶ基準は**柔軟性・制御性・学習コスト・監査性・再現性のトレードオフ**  
- 任せ方は**読み取り専用 → 人間レビュー付き → 限定自動化**の段階方式で  
- AI＋CLI or MCP連携で**自動ETLが現実に**  
- **Airbyte・Fivetran・dbt・BigQuery・S3**などとも組み合わせ可能  
- 気をつけるべきは**権限・ログ・レビュー**の3点セット  
- 説明するときは「すごい技術」ではなく「**戻せるリスク設計**」として語る  
- 将来的には「**AI ETLエンジニア**」という役割が一般化するかも？

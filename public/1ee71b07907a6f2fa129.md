今まで弊社ではツールの導入があまり進んでいない状況でした。ただ、環境が整うのを待つのではなく、有志のAI-TF（AIタスクフォース）で申請のロジックを自分たちで組み立てた結果、ついに経費の申請がおり、GitHub Copilot Businessを4名でトライアルすることが決まりました。

この記事では、製品・プランの選定理由、トライアルの設計（終了時の判定基準を含む）、そして実際に承認された経費申請の文面をまとめます。「うちはツールが導入されないから……」と感じている方が、自分たちで稟議を通すための材料になれば幸いです。

## 計画
何かしらAIツールを導入し、効率を上げたり、作業をやりやすくしたいというイメージが
TFのメンバー内にあることがわかったので、製品のリストアップを開始しました。
その中で、GitHub Copilotが第一候補に上がりました。
理由としては、
- Freeプランも最近登場し、業務外で試したところ、今後も継続的に利用する価値が高そうだと感じた
- TFのメンバーの前職でも利用していた
ためです。

このとき「最初から全エンジニアに導入する」という選択肢もありました。
ただ、全エンジニアに導入するとか、どんなことはやってはいけないとかの判断軸は会社や組織ごとに異なり、
他社事例をそのまま持ってきても客観性がありません。
そこで全員導入の即効性は捨てて、まず複数人でトライアルを行い、自社の判断材料を集めてからこれ以降の導入計画をまとめるという流れとしました。
### メンバー
トライアルメンバーは業務カバーを網羅させるべく、下記としました。
- Flutterメイン x 1名
- E2EなどのTypeScriptがメイン x 1名
- LaravelなどPHPがメイン x 2名

TF外のメンバーだったり、新卒入社だったり、中途だったりと色々なメンバーを巻き込めると良さそうです。

### 期間
1ヶ月

あまり長くしても、使わない期間などが発生するため、短めに設定しました。

### 費用
19ドル x 4名 = 76ドル(約12,000円)

金額によって承認フローに違いがあったり、インパクトが違うという場合は、
人数調整などが必要かもしれません。

### 期待効果
- AIを活用した開発効率、品質の向上
- 各プログラミング言語やタスクにおける適用可能性の評価
- 求職者やステークホルダーへのアピール

### トライアル終了時の判定基準
「なんとなく便利だった」だけでは、終了時に全社導入のGo/No-Goを判断できません。
そこで、実測値はトライアル中に集めるとして、終了時に何を見て判断するかの観点を先に決めておきます。

| 観点 | 全社導入を提案できる状態 | 見送り・縮小を検討する状態 |
| --- | --- | --- |
| 利用の継続率 | 期間の後半になっても日常的に使われている | 途中から起動されなくなる・存在を忘れられる |
| 提案の受け入れ率（体感） | 提案をベースに書き始める場面が日常的にある | 提案を消す・直す手間の方が目立つ |
| コーディング以外への波及 | テストコードやドキュメント作成にも効く | 単純な補完以外に用途が広がらない |
| セキュリティ懸念 | 除外設定などの運用ルールで吸収できる | 運用でカバーできない懸念が見つかる |

ポイントは「何が起きたら見送るか」まで先に言語化しておくことです。
ここを決めずに始めると、導入ありきの儀式的なトライアルになってしまいます。

## 準備
経費申請までに必要だった準備について触れます。

### 製品理由
数ある製品の中でGitHub Copilotを選定した理由は下記です。
- VSCodeやAndroidStudioのプラグインとして利用可能
- 元々GitHubを利用していたため、同じエコシステムでの利用でリスクが低減される

この理由が合致する、AIに限らず、役に立ちそうなツールが、
他には無さそうという判断ができたのも大きいです。

#### Copilotを選ばないシナリオ
逆に言うと、前提が変われば結論も変わります。
- GitHubをそもそも利用していない → エコシステムの利点が消えるため、他製品と横並びで比較し直す
- コード補完よりも調査や設計の壁打ちが主用途 → 汎用のチャット型AIで足りる可能性がある
- IDEや既存サービス付属のAI機能で要件を満たせる → 追加費用を払う理由がない

「自社の前提でどれが残るか」まで整理しておくと、申請時に選定理由を聞かれても答えやすくなります。

### プラン選定理由
料金プランを確認すると、候補となる3つのプランがありました。
1. Free
1. Pro
1. Business

Freeプランでもトライアルはできますが、実際のプロダクトや開発工程でどのような感触なのかを知りたいため、除外されました。
Proプランは指定したファイルを Copilot から除外するという機能がなく、セキュリティーや品質の観点から除外されました。
Businessは製品での利用も問題ないことから、こちらをトライアルの対象に決めました。

## 申請の例
あくまでも例ですが、下記が実際に承認された申請の内容です（固有名は伏せています）。
「目的 → 背景 → プラン選定 → 導入計画 → 費用 → 期待効果」という構造ごと流用できるので、
金額やメンバーを差し替えて自社用のテンプレとして使ってもらえればと思います。
稟議を通すのも、仕組みを動かすためのエンジニアリングの一部です。

目的:
技術開発本部としてAI技術の活用を促進するため、GitHub Copilotのトライアル導入を実施します。これにより、利用の必要性や投資対効果を検証し、社内展開の可能性を評価します。

背景:
GitHub CopilotはVSCodeに統合可能で、エンジニアが最も使用する環境に適しているため選定しました。セキュリティ面の懸念については、既存で利用中のGitHub製品と同じエコシステム内で運用されるため、リスクが低減できると判断しています。

プラン選定:
GitHub CopilotにはPro、Business、Enterpriseのプランが存在しますが、Businessプランは管理機能が含まれており、社内での利用に最適であると判断しました。本プランの利用料金は1人あたり月額19ドルです。
AI-TF内でGitHub Copilotを利用されていたのがEさんだけで、前職でもBusinessプランを利用されていたそうです。

導入計画:
以下の4名が、言語やタスクの違いを考慮してトライアルを実施します。それぞれのフィードバックを基に評価を行います。

Aさん: PHP（製品X・製品Y開発）
Bさん: Dart（製品X・製品Z開発）
Cさん: TypeScript（製品X・E2Eテスト開発）
Dさん: PHP・Dart（製品X・製品Z開発）
費用:
月額19ドル × 4名 = 76ドル/月 (1ヶ月間のトライアルを予定)
約11,867.70 円 (156円/ドル換算)

期待効果:
AIを活用した開発効率、品質の向上
各プログラミング言語やタスクにおける適用可能性の評価
求職者やステークホルダーへのアピール

:::note info
この申請文のポイントは、金額が小さく・期間が短く・終了時に判断材料が残る構造になっていることです。
承認する側から見ても「1ヶ月・76ドルで全社導入の判断材料が手に入る」なら、YESと言いやすいはずです。
:::

## 次回以降
トライアル2週目に入ったので、上で決めた判定基準に沿って評価やフィードバックを集め、実際に導入の計画を考えていきます。

また、トライアルの結果がどちらに転んでも、
- 判定基準の置き方（何が起きたら見送るか）
- 承認された申請文の構造

は次のツール検討にもそのまま使い回せる資産です。「リストアップ → 判定基準を先に決める → 小さくトライアル → 申請」という流れごとTF内のナレッジとして残し、AIツールに限らず社内のツール導入の型にしていきます。
